Summary

Build a lightweight task-runtime library for the PSoC 6’s Cortex-M4 and Cortex-M0+ cores, comparing runtime and costs of weighted static assignment, work stealing, and cost-aware scheduling. An initial profiling phase estimates per-core execution and communication costs, and the scheduler combines these estimates with core availability, core capabilities, and task dependencies to decide how to distribute tasks.

Background

Applications submit registered operations, input buffers, sizes, and dependencies. Benchmarks include controlled task graphs and representative signal- or image-processing workloads.

Benchmark selection is tentative.

The challenge

Unequal core capabilities, shared-memory contention, dependencies, and dispatch overhead. Investigate when dynamic balancing outperforms a tuned static schedule.

Resources

Dual-core PSoC 6, C/C++, Infineon IPC examples (these are the primitives they provide for safe cross-core memory accesses), and hardware timers. We implement the runtime ourselves.

Goals and deliverables

  • Plan: Implement the three policies and measure correctness, execution time, idle time, and memory usage against M4-only and weighted static baselines.
  • Stretch: Extend to two boards over SPI or UART and investigate remote assignment and batching. This adds the complexity of considering very low bandwidth wired communication bottlenecks.
  • Fallback: Independent jobs with fixed calibration before dependency graphs.

Platform choice

Unequal cores, shared SRAM, and constrained memory in a platform where firmware directly manages inter-core coordination. This lets us study whether scheduling mechanisms remain worthwhile when their overhead consumes a meaningful fraction of the available processing and memory resources.
